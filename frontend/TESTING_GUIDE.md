Offline-First Features — Testing Guide

This guide explains how to test the offline-first crop recommendation and symptom-check features locally and in a presentation.

1) Setup
- Start frontend dev server: `npm install` then `npm run dev` in `frontend/`.
- (Optional) Start backend: `cd backend && pip install -r requirements.txt && uvicorn app.main:app --reload`.

2) Files added
- `src/data/offline-crop-database.ts` — crop dataset
- `src/data/soil-analysis-offline.ts` — deterministic soil analyzer
- `src/data/fertilizer-offline.ts` — fertilizer calculator
- `src/services/offline-crop-engine.ts` — recommendCropsOffline()
- `src/data/disease-symptom-database.ts` — symptom rules

3) Crops Page — What to test
- Open the app and go to Crops page.
- Tab: Recommendations
  - Toggle network offline in browser DevTools (Network > Offline).
  - Move N/P/K sliders and click Analyze.
  - Confirm you get immediate offline recommendations (badge “Offline Mode” and top suggestions with confidence bars).
  - Re-enable network and repeat — the app will prefer the API when online.

- Tab: Soil Analysis (ALWAYS offline)
  - Enter soil values and click Analyze.
  - Confirm analysis runs even while offline, shows health score, pH status, and recommended amendments.
  - Verify suitable and avoid crops list is populated.

- Tab: Fertilizer (ALWAYS offline)
  - Enter crop and area, click Calculate.
  - Confirm fertilizer quantities, schedule and estimated cost appear even when offline.

4) Scan Page — What to test
- Photo Scan
  - Upload a clear leaf photo and click Analyze while online — the app will attempt AI call (if backend enabled).
  - Toggle offline and analyze — a deterministic/mock offline detection should return a result quickly with an offline disclaimer.

- Symptom Check (Offline)
  - Switch to Symptom Check tab.
  - Select a crop (e.g., Tomato) and answer questions (Yes/No).
  - Click Run Symptom Check — review ranked diseases, scores, and recommended actions.
  - Confirm this works with the network disabled.

5) PWA / Service Worker
- Build and serve the production build locally to validate PWA behaviors.
  - `npm run build` then serve the `dist/` folder (e.g., `npx serve dist`) and open in browser.
  - Install as PWA (Add to Home screen) and test offline flows again.

6) Presentation Tips
- Preload a set of images and sample slider values to demo quickly.
- Use Network throttling to show online → offline switching and demonstrate fallbacks.
- Highlight badges and labels: `📡 Online` vs `💾 Offline` and `📡 Offline Detection` disclaimers.
- Explain deterministic nature: offline engines use explicit scoring, so results are repeatable.

7) Debugging
- Open DevTools Console to see fallback logs and errors.
- If a file import fails, ensure TypeScript path is resolved and restart dev server.
